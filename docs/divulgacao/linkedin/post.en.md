**Compressing a table without turning it into a file nobody can open**

When a system stores or transmits a table, it picks between formats that repeat too much, like
JSON writing every field name on every row, and formats that compress well but become an opaque
block, like gzip, which you can only read after inflating it whole.

TCF sits in between. It compresses much like gzip, and the result stays text you can open and
read. Four people in a small record set: 451 bytes in JSON, 277 in CSV, 242 in TCF. And it
round-trips exactly, always.

```
#TCF.8M!2c=nome,2a=email,1c=cidade,14=plano,!cpf
Ana Souza
Bruno Lima
...
*3|Sao Paulo
Rio de Janeiro
```

`*3|Sao Paulo` says there are three identical rows there, written once. That visible structure
is what lets you ask questions without decompressing:

<!-- doctest: skip -->
```python
v = view(blob)                                  # decompresses nothing
v.count()                                       # 6
v.where("cidade", "Sao Paulo").sum("valor")     # 470.0, touches only cidade and valor
v.group_count("plano")                          # {'Premium': 4, 'Basic': 2}
```

On real data, 9 tables with 136k rows, it is 33% smaller than raw CSV.

The limits, because they matter: under gzip the formats tie, CSV wins at tiny sizes, and speed
optimization is the next cycle.
