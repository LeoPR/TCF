## What the library is

TCF losslessly encodes supported tabular and nested data into inspectable text. `encode()`
produces a string; `decode()` reconstructs the data. The representation uses references
and groups whose interpretation requires learning the markers. It is not a database,
an ETL tool or a serializer for arbitrary Python objects.

`pip install tcf-format` · MIT · pre-1.0 · Python 3.10 or newer · zero dependencies.

The public interface is documented in the [API reference](../reference/api.md).

## Claims and evidence

### 1. Representation and compression can be combined

JSON, CSV and TCF represent data; gzip, brotli and zstd compress the bytes of that
representation. These choices can be combined rather than being mutually exclusive.
In HTTP, compression can be indicated by `Content-Encoding`, and many libraries decompress
the body before handing it to the application. The question therefore includes **which
representation the process receives and parses after transport decompression**.

Decompression belongs in the application's CPU and memory budget even when the HTTP
library manages it.

### 2. Inspectable structure supports selective queries

A gzip file does not expose fields and values as directly inspectable text. They must be
decompressed to be interpreted, but this can happen as a stream without keeping the entire
decompressed content in memory. Gzip alone does not provide column access or operations
on the table's records.

Without an external compression layer, TCF exposes structure that `view()` can use.
The following example checks a customer list's round-trip and query results:

```python
from tcf import decode, encode, view

table = {
    "nome":   ["Ana Souza", "Bruno Lima", "Carla Nunes", "Diego Rocha"],
    "email":  ["ana@acme.com.br", "bruno@acme.com.br",
               "carla@acme.com.br", "diego@acme.com.br"],
    "cidade": ["Sao Paulo", "Sao Paulo", "Sao Paulo", "Rio de Janeiro"],
    "plano":  ["Premium", "Premium", "Basic", "Premium"],
    "cpf":    ["111.111.111-11", "222.222.222-22",
               "333.333.333-33", "444.444.444-44"],
}

wire = encode(table)
assert decode(wire) == table               # §RT: the round-trip comes before the number
assert len(wire.encode("utf-8")) == 242

v = view(wire)                             # nothing decoded yet
assert list(v.columns) == ["nome", "email", "cidade", "plano", "cpf"]
assert v.nrows == 4
assert sorted(v.distinct("cidade")) == ["Rio de Janeiro", "Sao Paulo"]
assert dict(v.group_count("plano")) == {"Premium": 3, "Basic": 1}
assert v.where("plano", "Premium").nrows == 3
assert v.column_bytes("cpf") == 59         # you can ask what each column costs
```

The queries above do not require reconstructing the entire table. The test checks their
answers and the representation's size; cost depends on the operation and column mode.

### 3. Size comparisons and sample scope

The example contains four records and five columns. Sizes are in bytes, with compact
JSON/JSONL and external compressors at their maximum levels:

| format | raw | gzip | br | zstd |
|---|---:|---:|---:|---:|
| JSON | 451 | 206 | 195 | 197 |
| JSONL | 449 | 205 | 194 | 194 |
| CSV | 277 | 177 | **162** | **165** |
| **TCF** | **242** | 206 | 185 | 193 |

In this example, TCF is smallest without an external compressor. Under gzip, JSON, JSONL
and TCF are within one byte of each other; compressed CSV is smaller than all three.
This does not establish a ranking for other data or compression levels.

[EXP-019](../../experiments/lab/clean/EXP-019-consistencia-0-8-4/) compares two representations
within TCF: hierarchical (`.8H`) and tabular records (`.8R`). Across eight samples of 800 rows,
the total fell from 390,863 B to 290,949 B, or **−25.6%**, with reductions of 4.1% to 46.6%
per sample and verified round-trips. This is not a comparison against CSV, JSON or gzip,
nor a scale test; the corpus includes real and generated data.

### 4. Nested data preserves structure and values

TCF reads the **data structure** the language builds from JSON, not the JSON text. The
round-trip preserves supported values and structure, including nested objects, arrays,
`null` and booleans; it does not preserve the formatting of the original JSON document.

Two records with a list inside: compact JSON is 184 B, TCF is 166 B, and with the opt-in CPF
filter it is **144 B**.

The encoder decomposes the object into columns by field. Each field name appears once
in the header. An example hierarchical header is:

```
#TCF.8Hnome:21,cpf:38,ativo:11b,fones#:6[
```

### 5. Candidate selection has a defined scope

> For each column, the encoder generates the candidates and writes the **smallest**:
> `min(tcf, raw, dictionary, split)`.

This choice bounds the size of each column's body by the alternatives the encoder evaluates,
including the raw representation. It does not guarantee that the complete file is smaller
than any CSV or JSON: headers and metadata also take space.

With `sort_by`, sorting is also a candidate: the encoder compares both versions and keeps
the smaller one. The option permits changes to row order, which is no longer part of
the reconstruction contract. Use it only when order does not matter.
[EXP-019](../../experiments/lab/clean/EXP-019-consistencia-0-8-4/report.md) records checks
of that choice on its samples.

### 6. How the contract is verified

The checks serve different purposes:

**The §RT rule**, which is process and not code. It is written as an invariant in the project
guide, and says `decode(encode(x)) == x` comes before any number: without a round-trip, the
number does not enter prose, a table, or a commit.

**The byte-canonical gates**, which pin the expected output of known sets and fail red if a byte
changes. That is what stops an optimization from changing the wire unnoticed.

**The pinned performance baseline**, with the case matrix locked by hash. It refuses to compare
two runs when the matrix or the plan differ, rather than joining what does not join.

### 7. Cost depends on how the data is reused

`encode` searches for patterns; `decode` reconstructs the chosen representation without
repeating that search. `view` can avoid unnecessary materialization, but may also need
to decode entire columns. There is no fixed timing ratio between these operations.

Data prepared once for many reads amortizes encoding cost. Data personalized for every
request repeats it. Performance measurements need to identify the workload, version,
environment and instrument, not just a speed ratio.

### 8. Markers describe different patterns

`*N|` represents identical consecutive values. `*N+delta|` represents a constant-step
sequence; `*N~d1,d2,...|`, a sequence with periodic steps. For example, `*12+5|\100`
describes twelve values starting at 100 with a step of 5.

These markers expose counts and progressions, but do not guarantee that every query
can operate without expansion. Implemented paths depend on the column mode and are
documented in the [query reference](../reference/lazy-view.md).

## Limits to retain in adaptations

- Size results belong to the measured data and settings. The small example does not
    demonstrate performance at scale or a universal advantage over external compressors.
- Encoding and querying have different costs; both need measuring for the intended use.
- The package is pre-1.0, without strict compatibility guarantees between minor versions.
- This page's comparisons do not evaluate Parquet, ORC or other storage formats.
- Current work and priorities are maintained in [STATUS.md](../../STATUS.md) and
    [ROADMAP.md](../../ROADMAP.md), not inferred from this announcement.
